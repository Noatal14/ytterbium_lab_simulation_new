# Data directory

This directory stores project data, result snapshots, and generated simulation artifacts.

## What is here

The files in this directory fall into a few broad categories:

### Fixed inputs and generated outputs

Some files in this directory are reused as fixed inputs for later analysis or optimization runs, while others are generated outputs kept for reproducibility and comparison.

Examples include:

- Zeeman survivor arrays (`*.npy`) reused as fixed MOT inputs
- JSON summaries produced by optimization runs
- historical result sets kept for comparison and reproducibility

### Optimization summaries

Several JSON files in this directory record optimization outcomes from the MOT tuning workflow. These are usually keyed by run parameters and may be regenerated by rerunning the corresponding optimization script.

### Binary results

The `.npy` files contain arrays of particle states that survived the Zeeman slower and can be reused as fixed input ensembles for later MOT runs, allowing different MOT parameters to be compared using the same Zeeman-survivor population. These are important intermediate outputs and may come from stochastic simulations.

## Naming conventions

The project uses a fairly direct naming scheme:

- `mot_optimization_summary.json` — aggregate optimization output
- `mot_optimization_fixed_s0_*.json` — fixed-s0 optimization summaries
- `mot_dt_scan_zeeman_survivors.npy` — Zeeman-survivor dataset used in timestep scans
- `zeeman_survivors_states.json` — saved Zeeman-state output in JSON format

These names are descriptive rather than rigidly standardized, but the intent is usually clear from the file name.

## Regenerating data

Not every file in this directory is a permanent frozen artifact. In particular:

- optimization summary files can be regenerated by rerunning the corresponding optimizer
- survivor arrays can be recreated by the Zeeman-stage workflow in `split_simulation.py`
- some analysis output can be rebuilt from the same simulation inputs

The repository should therefore treat this directory as both a storage location and a cache of reusable research artifacts, not as a strict immutable archive.

New `.npy` survivor ensembles are ignored by default because they can be large and reproducible. Existing tracked arrays remain tracked. JSON result summaries are not ignored automatically; review them deliberately before committing.

## Do not delete

Existing tracked results should not be deleted unless there is a clear and intentional reason to do so. The current directory contains useful historical research output and should be preserved as-is unless a workflow update specifically requires its replacement.
